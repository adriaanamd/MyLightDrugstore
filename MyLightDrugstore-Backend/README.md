# MyLightDrugstore Laravel backend

This directory contains the Laravel modular monolith for the MyLightDrugstore
refactor. It serves the `/api/v1` contract documented in the repository root's
[`API-DOCS.md`](../API-DOCS.md) for the React Feature-Sliced Design frontend.

The backend requires PHP 8.3.36+, 8.4.27+, or 8.5.12+ on the matching branch.
Those are the patched releases for PHP2Shell (CVE-2026-109618 and
CVE-2026-109619). Both Laravel entrypoints fail closed on older runtimes, and
all PHP workers must be restarted after an upgrade.

## Architecture

Business code is grouped by module under `app/Modules`:

- `Identity` handles session authentication, passwords, and roles.
- `Catalog` owns medicine definitions.
- `Inventory` owns receipts, lots, adjustments, and movements.
- `Sales` owns carts, sale lines, payment state, cancellation, and stock reservations.
- `Users` owns administrator staff-account management.
- `Reporting` owns read-only inventory and sales reports.
- `Operations` owns backups, audit events, and server time.
- `Security` owns encrypted data at rest and username lookup digests.
- `Transport` owns the RSA-OAEP key exchange and AES-256-GCM request/response envelope.

Each module separates `Domain`, `Application`, `Infrastructure`, and
`Presentation` concerns. Controllers translate HTTP input to application
commands; persistence and business rules stay outside controllers. The
application remains one Laravel deployment and one relational database, with
module boundaries enforced by architecture tests.

## Local setup

```bash
composer install
cp .env.example .env
php artisan key:generate
php artisan migrate
```

For local development, SQLite is sufficient. Use a separate MySQL or MariaDB
database for deployment and migration smoke checks. Generate transport and data
encryption keys outside the repository; never commit private keys or real
database dumps.

## Verification

The same lanes used by CI can be run locally:

```bash
composer validate --strict --no-check-publish
composer test
composer run analyse
vendor/bin/pint --test
```

The PHPUnit suites are intentionally separated by responsibility:

- `Unit` tests value objects and cryptographic primitives.
- `Architecture` tests module boundaries, route composition, authorization, and
  API documentation parity.
- `FeatureFoundation` tests transport, security, and HTTP error behavior.
- `FeatureBusiness` tests catalog, inventory, sales, identity, users,
  operations, and reporting workflows.
- `FeatureTransport` tests encrypted request and response integration.

Coverage reports are generated by CI and are written locally under
`storage/framework/cache/coverage`, which is ignored by Git. PHPStan runs at
level 9 with no baseline. Pint is the formatting gate.

## Security model

The API uses Laravel's HTTP-only session cookie and CSRF protection. State
changing requests also use the AES-256-GCM transport envelope established with
the RSA-OAEP public key endpoint. Staff usernames and full names are encrypted
at rest; a keyed HMAC digest supports normalized username lookup without
storing plaintext search columns. Backup artifacts are encrypted and kept on a
private filesystem disk. Error responses and backup failure records use generic
messages and do not expose SQL, keys, or stack traces.

Read the API contract before adding routes. New endpoints must be documented,
registered through a module route file, covered by feature tests, and included
in the authorization and transport architecture checks.
